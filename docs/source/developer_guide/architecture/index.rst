============
Architecture
============

Architecture documentation explains how MC/DC translates flexible Python model
definitions into particle-transport execution. The main path follows the model
through compilation, runtime preparation, Python execution, Numba-CPU acceleration,
and finally the Numba-GPU and Harmonize layers. MC/DC's architecture flow and
component responsibilities are presented below.

Architecture Flow
-----------------

MC/DC has three distinct preparation and execution stages:

#. **Model compilation** discovers the Python objects owned by a
   :class:`mcdc.Simulation`, deduplicates them, and assigns simulation-local
   identifiers.
#. **Runtime preparation** converts the compiled model into the structured
   ``simulation`` state and flat ``data`` array consumed by transport.
#. **Backend execution** runs the shared transport implementation through
   Python, Numba-CPU, or Numba-GPU.

Component Responsibility
------------------------

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - Component
     - Responsibility
   * - ``mcdc/object_``
     - Defines the Python-side model, configuration, and runtime-state classes.
   * - :class:`mcdc.Simulation` in ``mcdc/object_/simulation.py``
     - Owns model roots and configuration and controls compilation,
       visualization, and execution.
   * - ``mcdc/code_factory/python_objects_compiler.py``
     - Discovers and registers the connected Python object graph.
   * - ``mcdc/code_factory/numba_layers_generator.py``
     - Derives structured dtypes, packs runtime state, generates accessors, and
       initiates GPU-specific preparation when requested.
   * - Runtime ``simulation`` and ``data``
     - Generated by ``numba_layers_generator.py``; store fixed-layout state and
       variable-length numerical data,
       respectively.
   * - ``mcdc/mcdc_get`` and ``mcdc/mcdc_set``
     - Provide generated, structured access to fields stored in ``data``.
   * - ``mcdc/transport``
     - Implements the particle-transport algorithms consumed by every
       execution backend.
